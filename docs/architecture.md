# Architecture

This service is a **modular monolith** built with NestJS 12 and organised by
Domain-Driven Design. Each business capability is a bounded context under
`src/modules/<name>/` with four layers. The dependency direction is enforced by ESLint
(`eslint-plugin-boundaries`), so a violation fails the build rather than a code review.

```
src/
├── main.ts                    process entry point
├── app.module.ts              composition root: wires modules + global guards/pipes/filters
├── app.setup.ts               HTTP configuration shared by the server and the e2e tests
├── config/                    typed, validated configuration (Zod) — no process.env elsewhere
├── shared/                    shared kernel, same four layers as a module
│   ├── domain/                Entity, AggregateRoot, ValueObject, EntityId, DomainError, Clock, Role
│   ├── application/           UseCase, EventPublisher port
│   ├── infrastructure/        Mongo connection, logging, system clock, event bus adapter
│   └── presentation/          problem-details filter, schema pipe, auth decorators, pagination
└── modules/
    ├── games/                 Games catalog + lifecycle policy (retire / discount)
    ├── publishers/            Publishers
    ├── iam/                   Identity & access: accounts, sessions, tokens, guards
    └── health/                liveness / readiness probes
```

## Layers inside a bounded context

```
src/modules/games/
├── domain/                    pure TypeScript, no framework imports
│   ├── game.ts                aggregate root with behaviour (applyDiscount, update, ...)
│   ├── game-id.ts             identity (UUID generated by the domain, not the database)
│   ├── value-objects/         Price (cents), GameTitle, Tags, Discount
│   ├── catalog-lifecycle-policy.ts   domain service: ageing rules
│   ├── game.repository.ts     repository *port* (interface + DI token)
│   └── game.errors.ts         typed domain errors (mapped to HTTP later)
├── application/               use cases: orchestration only, one class per operation
│   └── use-cases/*.use-case.ts
├── infrastructure/            adapters: Mongoose schema + mapper + repository, event listeners
├── presentation/              HTTP: controller, Zod request/response schemas, presenters
├── testing/                   in-memory test doubles for the ports (specs only)
├── games.module.ts            Nest wiring: binds ports to adapters
└── index.ts                   PUBLIC API — the only file other modules may import
```

| From \ To      | domain | application | infrastructure | presentation | other module `index.ts` |
| -------------- | :----: | :---------: | :------------: | :----------: | :---------------------: |
| domain         |   ✅   |     ❌      |       ❌       |      ❌      |           ❌            |
| application    |   ✅   |     ✅      |       ❌       |      ❌      |           ✅            |
| infrastructure |   ✅   |     ✅      |       ✅       |      ❌      |           ✅            |
| presentation   |   ✅   |     ✅      |       ❌       |      ✅      |           ✅            |
| `*.module.ts`  |   ✅   |     ✅      |       ✅       |      ✅      |           ✅            |

Every row may also use the matching (or lower) layer of `src/shared`. The domain layer may
not import `@nestjs/*`, `mongoose`, `zod`, `express`, `argon2` or logging libraries; the
application layer may import only `Injectable`, `Inject` and `Optional` from Nest.

### Why these rules

- **Domain is the source of truth.** Value objects (`Price`, `Siret`, `Email`, ...) validate
  their invariants on construction, so an invalid aggregate cannot exist in memory. The HTTP
  schemas repeat the cheap shape checks for a fast 400, but business rules live once.
- **Use cases are thin.** They load aggregates through ports, call behaviour on them, persist,
  and publish events. They are unit-tested with in-memory repositories in milliseconds.
- **Adapters are replaceable.** Mongo, Argon2, JWT and the event bus sit behind interfaces
  declared in the domain/application layers and are bound in the module file.
- **Modules talk through contracts.** The games context depends on the `PublisherLookup` port
  and the `PublisherDeletedEvent` exported by `publishers/index.ts`, never on its entities or
  repository. Deleting a publisher publishes an event; the games context reacts by detaching
  the reference (eventual consistency inside the process).

## Request pipeline

```
HTTP ─▶ helmet / CORS ─▶ pino request log ─▶ ThrottlerGuard ─▶ AccessTokenGuard ─▶ RolesGuard
     ─▶ StrictSchemaValidationPipe (Zod, fails closed) ─▶ controller ─▶ use case ─▶ domain
     ◀─ presenter (entity → response DTO) ◀─────────────────────────────────────────┘
     ◀─ ProblemDetailsFilter (any error → RFC 9457 application/problem+json)
```

- **Validation**: Nest 12's Standard Schema support lets Zod schemas ride on `@Body()`,
  `@Query()` and `@Param()`. The same schemas generate the OpenAPI document. The custom pipe
  throws if a route parameter has no schema, so unvalidated input is impossible to ship.
- **Errors**: domain errors extend `NotFoundError`, `ConflictError`, `AuthenticationError`,
  `AuthorizationError` or `InvariantViolationError`; the filter maps those to 404 / 409 / 401 /
  403 / 422 and includes a stable `code`. Unexpected errors become a generic 500 and are logged
  with the request id.
- **Auth**: stateless HS256 access tokens (15 min) plus rotating refresh tokens (7 days) whose
  id is stored on the user, so a refresh token can be revoked (logout) and reuse is detected.
  Roles are `user` (may write catalog data) and `admin` (may also run maintenance).

## Persistence

Aggregates are mapped explicitly (`*.mapper.ts`) between domain objects and Mongoose lean
documents. Identifiers are UUIDs generated by the domain; money is stored as integer cents.
Repositories `replaceOne(..., { upsert: true })` so a save is a full, idempotent write of the
aggregate. Unique indexes (SIRET, e-mail) back the application-level checks and duplicate-key
errors are translated into the matching domain `ConflictError`.

## Testing strategy

| Level | Location                | Runs against                                   |
| ----- | ----------------------- | ---------------------------------------------- |
| unit  | `src/**/*.spec.ts`      | domain objects, use cases with in-memory ports |
| e2e   | `test/**/*.e2e-spec.ts` | the full app + in-memory MongoDB via supertest |

`pnpm test` runs both; coverage thresholds are enforced in `vitest.config.ts`.
